# Web engineering

Use for engineering decisions and changes to supported web projects. Use the relevant project guidance for unrelated platforms or standalone operational tasks.

1. Read the request, affected code and existing project decisions. For new projects or material changes, use [project selection](references/project-selection.md). Ask only about consequential unknowns and document assumptions. Obtain approval for material technology decisions before implementation.
2. Select a row in [task routing](references/tasks.md). Load only the applicable references and workflow sections. Use the [index](references/index.md) when locating a supporting template or example.
3. Apply [engineering standards](references/standards.md). Keep valid existing conventions and use the smallest change that delivers the outcome. When a security or correctness conflict cannot be resolved within scope, explain the conflict and request the needed decision.
4. Implement through the normal entry point, run the applicable checks, and update [living documentation](references/project-documentation.md) for changed behavior or decisions. Report actual verification and remaining limits.

Profiles are conditional. Use [React](references/react-dashboard.md) for a React SPA, [Next.js](references/next/profile.md) for a Next.js app, [external API guidance](references/external-api.md) for integrations, [Supabase](references/supabase/profile.md) for an approved Supabase backend, and [compatibility](references/compatibility.md) for combined or hybrid systems. Load historical evidence only for maintenance or when a decision depends on it.
