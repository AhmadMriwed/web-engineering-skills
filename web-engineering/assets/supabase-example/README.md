# Neutral workspace notes

This fixture models owner writes, read-only scoped admin access, current workspace membership and separate user-owned file namespaces. The storage sample represents personal files, independent of workspace membership. Add resource membership checks to the storage policy when a file belongs to a workspace. Workspace and membership provisioning is out of client scope.

1. In a new disposable directory with a pinned Supabase CLI and container engine, run `supabase init`. Copy the migration and seed into the generated directory.
2. Start locally and run `supabase db reset`. Run `psql -v ON_ERROR_STOP=1 -f checks/policy-assertions.sql` using the connection parameters reported for that local stack. The assertions roll back. The seed creates synthetic SQL principals without sign-in credentials. Add synthetic Auth API users separately for end-to-end sessions.
3. Regenerate the checked-in `src/database.generated.ts` with `supabase gen types --lang typescript --schema public`. Install Supabase JS 2.x with your pinned TypeScript toolchain, and compile the modules in `src/` in strict mode. Use the local public URL and publishable key supplied by the CLI. Treat error causes as internal diagnostics.
4. To verify managed-service behavior, sign in as synthetic users and exercise database, Storage and Auth through their APIs. The SQL assertions cover policy predicates under database roles. Check file size/type limits and signed access through Storage itself.

The checked-in type file was generated by Supabase’s upstream TypeScript generator from the synthetic PostgreSQL catalog. Regenerate after schema changes, using the version of the generator pinned for your project.
