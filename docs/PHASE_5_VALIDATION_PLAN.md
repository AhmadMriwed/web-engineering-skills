# Phase 5 independent agent validation plan

Pending owner authorization. Use fresh neutral workspaces, synthetic accounts and disposable services. Install only the skill folder in the consumer under test. Run an unprompted discovery trial and a separate explicit invocation trial where supported. Record agent/version, activation event, references read, questions, approvals, diff, commands, results and scope violations. Hide the expected path and undisclosed facts from the agent. Respond to material questions with scripted answers. Skip production and release work.

| Project and initial user request | Hidden decision and expected discovery/approval | Expected activation, loading and documents | Functional, security and testing acceptance |
| --- | --- | --- | --- |
| A. Build an inventory dashboard against the supplied REST contract | Existing API is explicit. Ask only about missing resource permissions. Recommend React + existing API and obtain stack approval. | Automatic and explicit trials. Discovery, SPA, API, dashboard workflow. Profile, feature and API docs. | Filter and paginate, verify rejected writes and expired sessions, run build and contract tests. |
| B. Build an English/Arabic guide site for search discovery | Confirm canonical origin if absent and determine freshness. Recommend Next.js and approve the render strategy. | Discovery, Next profile, SEO/locale routes. Profile and route plan. | Direct translated routes, RTL, canonical and hreflang, robots/sitemap and build/HTTP checks. |
| C. Build a team notes dashboard with personal files | No backend yet. Determine ownership and file limits. Compare alternatives and obtain React/Supabase approval before scaffolding. | Discovery, React, Supabase identity/database/services. Profile, migrations and policy matrix. | Positive and negative actor checks for DB and file APIs. No privileged token in client. |
| D. Build a public catalog with private saved items | Establish session and freshness split. Approve Next.js and selected backend. | Next rendering, Supabase app/identity when approved. Route and auth docs. | Public caching and sequential private-user isolation, cookie expiry, direct protected entry and build. |
| E. Build a public catalog and admin panel sharing a backend | Ask who owns deployments and identity when unspecified. Compare one app with split ownership. Approve selected topology. | Compatibility, selection, chosen profiles. ADR, contracts, domains and runbooks. | Verify independent deploy/version skew, permission checks and cross-app navigation. |
| F. Fix a focus regression in the supplied React app | Framework and component conventions are discoverable. Ask no stack question. Migration requires separate approval. | UI or bug route and relevant interaction reference only. Update affected docs when contract changes. | Preserve behavior, verify keyboard/focus and smallest change. No dependency churn. |
| G. Build a static product landing with supplied content | No accounts or persistence. Confirm only consequential omissions. Approve Next.js/static delivery option. | Discovery, Next public UI and SEO. Profile, content and deployment docs. | Working CTA, accessible markup, RTL if requested, production build, no new backend or invented claims. |

Fail a trial if activation is absent when expected, unrelated profiles dominate loading, the agent asks for answered details, changes a material technology without approval, violates a trust boundary, invents evidence, or reports unrun tests as passing. Score discovery and scope, routing, implementation, actual validation and documentation separately. Repeat representative trials across supported consumers. Report failed/fallback and explicit invocations separately. No Phase 5 trial has been executed.
