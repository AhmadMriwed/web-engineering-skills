# Phase 2 merge plan

The owner approved this plan. Its execution is recorded in the [integration report](PHASE_2_INTEGRATION.md). The original staging context follows.

The central Phase 1 files were untracked in an unborn Git repository at acquisition. This proposal uses an isolated copy of the 25 deliverables. The central directory remains the approved React baseline.

1. Review the [report](PHASE_2.md), [comparison](REACT_NEXTJS_COMPARISON.md), and [coverage audit](PHASE_2_COVERAGE_AUDIT.md). Approve the new rule IDs, shared core, technology selection and compatibility scope.
2. Compare the canonical directory and the staging copy. Verify that baseline files still match the snapshot or reconcile concurrent changes file by file. Use the report's file inventory to review the intended changes.
3. After approval, apply only the reviewed new and modified deliverables. Retain all original rule definitions, React references, test scripts and documentation. Keep private provenance and temporary dependencies outside the canonical tree.
4. Run both skill validators, React assertions and React DOM smoke. Build the neutral Next fixture and run its local HTTP checks. Verify relative links, evidence references, profile routing and privacy.
5. Record Phase 2 approval and remaining gaps. Request separate authorization and the Supabase reference before Phase 3.

Changes introduce a Next profile, three rule IDs, shared principles, compatibility and a route plan. React-specific rules and implementations are retained. No guidance or rule ID is deprecated. Existing workflows continue to route through the React profile.
