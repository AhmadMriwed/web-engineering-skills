# Knowledge maintenance

Allocate stable rule IDs by topic, in the form `WEB-DEC-001`. Keep the ID when clarifying the same requirement. Record replacements and migration implications when a rule changes meaning.

Assign each source a neutral ID such as `WEB-SRC-001`. Keep private provenance and reference repositories outside this workspace and outside release inputs. The private evidence record should capture the source location, branch, revision, file or symbol anchors, observed behavior, counterexamples, and validation method. Publish only sanitized observations, scope and confidence tied to source and rule IDs. Review distributable files and history for private material before release.

Classify findings as shared, profile-specific, conditional, corrective, project-specific, or pending verification. Record where an observed pattern applies and what would make it fail. Document competing practices and seek approval before adopting material changes. Track compatibility of the complete selected combination, with the validation method and limits stated separately.
