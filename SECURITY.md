# Security policy

This policy covers the initial v0.1.0 release.

Report unsafe authorization guidance, accidental secret exposure, and package integrity issues privately. If the published repository enables GitHub private vulnerability reporting, use that channel. Until a private channel is configured, seek one from the maintainer before sending sensitive evidence. Public issue templates are for sanitized, non-sensitive reports.

Include affected version, relevant rule or file, a sanitized description, impact and suggested correction. Keep credentials, customer data and production endpoints out of reports. Give the maintainers time to investigate and coordinate disclosure. Treat real credentials as exposed and follow the affected organization's revocation procedures.
